# Adapters

Adapters validate connection configuration, publish capabilities, compile
semantic queries (where implemented), execute bounded requests, and normalize
results into OpenPlait dataframes.

| Package / module | Kind | Signals | TypeScript | Python |
| --- | --- | --- | --- | --- |
| `@openplait/adapter-clickhouse` · `openplait.adapters.clickhouse` | `ClickHouseDatasource` | traces, logs, metrics, tabular | Full semantic + native SQL | Native SQL execute |
| `@openplait/adapter-tempo` · `openplait.adapters.tempo` | `TempoDatasource` | traces | Full semantic + TraceQL | Native TraceQL search |
| `@openplait/adapter-loki` · `openplait.adapters.loki` | `LokiDatasource` | logs | Full semantic + LogQL | Native LogQL `query_range` |
| `@openplait/adapter-prometheus` · `openplait.adapters.prometheus` | `PrometheusDatasource` | metrics | Full semantic + PromQL | Native PromQL `query_range` |
| `@openplait/adapter-jaeger` · `openplait.adapters.jaeger` | `JaegerDatasource` | traces | Full semantic search | Semantic service-scoped search |

An adapter must be honest about its capabilities. Unsupported joins or
operations fail explicitly before execution.

TypeScript packages live under
[`typescript/packages`](https://github.com/openlit/openplait/tree/main/typescript/packages).
Python adapters live under
[`python/src/openplait/adapters`](https://github.com/openlit/openplait/tree/main/python/src/openplait/adapters).

<LangTabs ariaLabel="Validate adapter language">
  <LangTab label="TypeScript">

```ts
const validation = adapter.validateConfig(config);
const capabilities = await adapter.getCapabilities(config);
```

  </LangTab>
  <LangTab label="Python">

```python
validation = adapter.validate_config(config)
capabilities = await adapter.get_capabilities(config)
```

  </LangTab>
</LangTabs>

Connection configuration is server-side input. Query resources only carry a
datasource reference.

tabs, and [Agent Skills](/guides/agent-skills/) to wire adapters into an app.
